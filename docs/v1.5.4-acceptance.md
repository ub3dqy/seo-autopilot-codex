# v1.5.4 acceptance — Next.js metadata and site-verification accuracy

## Field input

The AIRSYS v1.5.3 checkpoint proved that:

- `SOURCE_FIRST` scope and browser-profile privacy exclusions work;
- active `cookies` routes remain in scope;
- `artifacts/**` and `tmp/**` produce no findings;
- 10 of 11 remaining deterministic findings were not actionable.

The false positives were:

```text
TECH-ROBOTS-001 for a valid src/app/robots.ts owner
TECH-SITEMAP-001 for a valid src/app/sitemap.ts owner
4 page-level rules for a Google ownership-verification file
4 page-level rules for a Yandex ownership-verification file
```

The real `NEXTJS-HASH-NAVIGATION-001` finding must remain.

## Required behavior

### Next.js metadata route ownership

Recognized endpoint owners:

```text
app/robots.ts
src/app/robots.ts
app/sitemap.ts
src/app/sitemap.ts
app/robots.txt
src/app/robots.txt
app/sitemap.xml
src/app/sitemap.xml
```

For `.ts`/`.js` owners, a default export is mandatory.

Acceptance:

```text
valid robots owner -> TECH-ROBOTS-001 absent
valid sitemap owner -> TECH-SITEMAP-001 absent
same filename without default export -> generic missing finding retained
live endpoint verification -> remains separate and NOT inferred from source
```

### Site-ownership verification files

Accepted Google contract:

```text
filename: google<token>.html
content:  google-site-verification: <same filename>
location:  repository root, public/, or static/
size:      <= 16 KiB
```

Accepted Yandex contract:

```text
filename: yandex_<token>.html or yandex<token>.html
content:  contains Verification: <same token>
location:  repository root, public/, or static/
size:      <= 16 KiB
```

Acceptance:

```text
recognized verification files -> zero page-level findings
recognized verification files -> zero safe fixes
recognized verification files -> audit_scope.excluded_site_verification_files
similarly named real pages -> remain scanned
classification records files_not_read=false because the small candidate file is read for exact matching
```

## Release gate

The exact source head and exact squash-merge commit must each pass:

```bash

```

Windows uses:

```text

```
