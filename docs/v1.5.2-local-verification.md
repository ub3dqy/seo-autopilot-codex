# v1.5.2 local verification

GitHub Actions are not used. The only accepted release evidence is produced locally from the exact public GitHub candidate and then again from the exact merged runtime commit.

## Portable command

```bash
python scripts/verify_local.py --release
```

## Supported Windows command

```text
VERIFY_LOCAL_WINDOWS.cmd --release
```

The Windows launcher uses `scripts/verify_local_utf8.py`, `-X utf8`, `PYTHONUTF8=1`, and `PYTHONIOENCODING=utf-8`. This is required because a Russian Windows console can otherwise expose CP1251 output while a captured child process contains replacement or other Unicode characters.

On 2026-08-26 an exact-candidate Windows run reached the unit-test step but the verification harness itself raised `UnicodeEncodeError` while printing `\ufffd` to a CP1251 stream. No GitHub mutation occurred. The harness-only defect is now covered by `tests/test_windows_utf8_gate.py`; the candidate must be rerun after that change. A PASS claim belongs in PR/release evidence only after the exact updated commit completes every recorded step.

Required coverage includes:

- all unit, lifecycle, transaction, rollback, installer, reporting, release, and source-version tests;
- CP1251-strict console regression for the UTF-8 Windows verification entry point;
- AIRSYS-shaped source-scope regression with archived HTML pages, temporary HTML pages, and browser-profile markers;
- zero findings and zero A-level candidates from `artifacts/**` and `tmp/**`;
- `EXCLUDED_SENSITIVE` browser-profile recording with `files_not_read=true`;
- deterministic Next.js source findings for hash navigation, mobile menu accessibility, sitemap dates, WebSite identity, and dynamic metadata ownership;
- source verification and tracked-source secret scan;
- two deterministic edition builds and reproducibility comparison;
- direct-from-ZIP version and scope/privacy smoke tests;
- SPDX SBOM, release asset verification, and post-build generated-tree verification.
